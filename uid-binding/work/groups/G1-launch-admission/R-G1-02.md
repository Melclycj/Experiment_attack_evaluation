# R-G1-02 — A's rendered uid is compared to a stored expectation not equal to that allocation uid's receiver-domain representation, allowing a distinct principal to match.

## 1 What the adversary does
A's rendered uid is compared to a stored expectation not equal to that allocation uid's receiver-domain representation, allowing a distinct principal to match.

## 2 How it would produce false attribution
- **Preconditions:** the stored comparand e_r of row r differs from r(u_r), the receiver-domain rendering of the uid of the lease r's reservation took, while rendering is faithful (p31: r injective, no sentinel alias; p32: v(f) = r(k)). Three departures from the frozen text would produce it: (i) T-01 writes a value other than the lease's uid into Session.expected_uid; (ii) a later transition overwrites the field with an observed or payload value; (iii) the engine's number domain is not the kernel's host domain — the engine sits in a user namespace whose map is injective but not the identity, so r(u_r) ≠ u_r for every pool uid while e_r = u_r, the host number from the pool; a task whose kernel uid maps to the number e_r would then match row r. A then needs a task at the matching uid: its own tasks at u_A for (i)/(ii) when the wrong value is u_A, or a task at the colliding uid for (iii), which is a G5 configuration question. Configuration: all three under the common abstraction (01 AA-06).
- **Transitions traversed:** T-01 (the write), T-09 (no uid in the prepared record), T-11, T-20 (a), T-21 (translation in the engine's namespace), T-22, T-23 (the comparison against the row's field), T-24 (D-ACC); T-67 for (iii), cited as a Step 1 fact (G5 owns it).
- **Sufficient condition violated:** C-03 p33 (the actual stored comparand e_r = r(u_r), in the same number domain). Cell D_33 → R-G1-02 unconditionally (02 §4); B(R-G1-02) = ¬H ∧ D_33. With p31 and p32 holding, the comparison is faithful to the stamp but measured against the wrong expectation: a sender whose rendered uid equals the wrong e_r passes T-23 and is labelled r although u(task_b, send_b) ≠ u_r — the chain of 02 §3 breaks at r(k(b)) = e_r = r(u_r). The retired selector q21 named the stored-field mismatch and routes here (02 §4, addendum F-02).

## 3 What stops it
expected_uid is written once at T-01 from the lease's pool uid, is never overwritten, and is compared in the engine's initial user namespace (C3), so e_r = u_r = r(u_r). The cut is at T-01 (preservation row T-01): the reservation takes the UidLease registered for the workspace and writes Session.expected_uid from it in the same decision (conn L254, L322; rr L560–561); the field is immutable after creation and may not be set to an observed value (conn L80; mech L263–266). In the prototype the Session is constructed inside launch() with expected_uid = lease.uid, the lease's uid taken only from the workspace record, and a text search at commit 3ec67985 finds no other write to the field (EV-186, lifecycle.py:139–150, confirmed on 2026-10-19); Session declares expected_uid write-once and a second assignment raises (EV-187). No later G1 transition carries a uid into the row: spawn_prepared holds digests, child_pid, sealed and copy_id only (conn L113; row T-09) — the spawner's record carries no uid or gid (EV-185) — the hello may not supply uid, agent_id or grant (conn L465; row T-12), and every message type with any of 13 identity-like fields added is invalid (EV-184); the comparison path passes the row's expected_uid to the C reader, which returns no observed uid, so nothing looks up or rewrites a row from the observed uid (EV-186; conn L424; T-23 as a Step 1 fact). The number domain: the pool holds host uids (conn L78), the kernel renders a stamp in the receiver's user namespace (EV-13), and the design requires the engine to be in the initial user namespace with the identity map (C3 / S13, optb L178; conn L87–89). The prototype's start-up check accepts only the single uid_map line 0 0 4294967295 and refuses service otherwise (EV-165, support.c:221); it recorded the identity map in the product entry (EV-163) and refused service under a one-line non-identity map (EV-164). That this namespace is the initial one is a deployment premise the self-check does not establish (val row 256; conn L89). The ABI half — decode as uid_t, no signed conversion (conn L423) — is p32, G2's.

## 5 Disposition
**supported under stated premises**
- Premises that must hold: C3 / S13 — the engine in the initial user namespace (deployment premise; the self-check catches a non-identity map but does not show the namespace is the initial one, val row 256); the pool holds host uids excluding 0, the overflow uid, invalid values and identities in use on the host (checked at start-up by EV-202, host accounts only through NSS, val row 131); AA-04 for the trusted caller's request; AA-01 (single executor) so that the one-decision write at T-01 is not interleaved. A design-layer and kernel-semantics conclusion, with the engine-side items realized in the prototype and checked; not a claim about a deployed system.
- Evidence limit (configuration, substrate, run dates): integration run of 2026-10-19 (pool uids 70000–70002). Shared limits: [coverage-uncertainties § Shared evidence boundary](../../convergence/coverage-uncertainties.md#shared-evidence-boundary-every-route-not-repeated-below). Limits of the checks: "no other write" of expected_uid rests on a text search (EV-186, val row 140 code reading only); the write-once guard admits a first assignment to a field still holding None, which expected_uid never does since it is set at construction to a pool uid; the self-check's negative case is one non-identity map in the integration run plus the unit suite's maps; the namespace observation of EV-213 (user:[4026531837]) is an inference about the initial namespace, not a reading at the pinned tree.

## 6 What remains
- Residual: case (iii) with an injective non-identity map is a configuration failure against S13 (T-67, G5's transition); the prototype's self-check now refuses service under any non-identity map, so the route's case (iii) leaves only the premise that the identity-mapped namespace is the initial one. A foreign kernel uid can match only if the map carries it to a pool number — R-G5-05's and R-G5-06's subject. An engine bookkeeping defect at T-01 (a wrong value written) is the honest-but-buggy case of 02 §0.3; the write-once rule localises it to one transition and one field, and the prototype has one such write.
- Design obligations surfaced: the T-01 and engine-start obligations of the earlier run are realized (EV-186, EV-165). Remaining: a deployment-time reading that the engine's namespace is the initial one (S13), which no engine check can supply.
