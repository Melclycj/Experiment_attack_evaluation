# R-G5-03 — A lawfully selects an effective/saved uid different from its real uid and an execution label relies on the unjustified single-uid interpretation.

## 1 What the adversary does
A lawfully selects an effective/saved uid different from its real uid and an execution label relies on the
unjustified single-uid interpretation.

## 2 How it would produce false attribution
- **Preconditions:** for a selected value to differ from the real uid, the sender's own set `{real,
  effective, saved}` must hold two values. The route therefore presupposes that step 11 left unequal values
  (C1 absent; 01 T-67, whose examples since version 9 name "unequal uid slots after `setresuid` → T-07's
  re-read outcome") — say real u_A and saved u_B — and that the agent nevertheless started. No other path
  grows the set: `no_new_privs` makes set-user-ID programs ineffective at `execve` (EV-05), the runtime and
  /work are mounted `nosuid` (optb steps 3–4), and without `CAP_SETUID` in the initial user namespace
  `setresuid` moves only among the set's members (EV-06). For an accepted wrong label the selected u_B must
  equal a row's comparand and the frame must arrive on that row's channel: pool uids are distinct per lease
  (01 §1), so u_B matches only row B's `expected_uid`, and the frame reaches row B only through B's
  agent-side endpoint (A-07, a stipulated input no frozen transition produces) or a G1 installation error
  (R-G1-02, R-G1-03). On A's own channel u_B meets row A's u_A and T-23 discards the frame (01 T-23).
  Configuration: all three under the common abstraction — the departure is in the spawn sequence, identical
  in C-LS, C-LP and C-R.
- **Transitions traversed:** T-07 with unequal slots and its re-read not failing (the T-67 departure) →
  T-08 → T-11 → T-20 (b): a `SCM_CREDENTIALS` naming the saved or effective uid, accepted because the uid is
  in `{uid, euid, suid}` (EV-08), the explicit path replacing the passive fill (EV-07, EV-09) → T-21 → T-22
  → T-23 (u_B equals the comparand only on B's channel) → T-24 (D-ACC labelled B). T-61 is the transition
  under which, within the premises, the own set cannot come to hold a second value.
- **Sufficient condition violated:** C-02 p22 — k(b), the selected own-set value, differs from
  u(task_b, send_b), the real uid at send; branch D_22 ∧ q09. The label is wrong because the chain of 02 §3
  reads the stamp as the sender's real uid, and the sender is a task of P_XA whose real uid is u_A while the
  row's label is B.

## 3 What stops it
C1 — spawn step 11's setresuid with three equal values, re-read by getresuid before the seccomp install so
that an unequal value fails the spawn with no SEALED, leaves the task's own set {u}, and the kernel's own-set
rule admits no other explicit value (T-07 outcome; preservation row T-61). The design writes the call as
`setresuid(u, u, u)` (optb step 11, L246–257) and, since the 2026-10-18 freeze, a check of it: after
`setresuid` and before the filter, `getresuid` re-reads the three values, and any value unequal to the
recorded uid gives FAIL(stage = uid), no filter installed, no SEALED (conn E-01 identity supplements,
L127–130; 01 T-07 outcome). A FAIL is a T-13 `spawn_failed`, so the row goes to CLOSED and no agent code
runs (step 12 is never reached). The re-read is in the drop function the bootstrap, the engine and the file
worker share; it was built and run (proposed rows below). With the three slots equal, the kernel's explicit
path accepts a uid only if it is in `{uid, euid, suid}` or the sender holds `CAP_SETUID` in its own user
namespace (EV-08); the sender holds no capability in the initial namespace — bounding set cleared,
`no_new_privs` (EV-05), all capability sets zero after the as-built drop (EV-74), `setuid(0)` refused (EV-70,
EV-74) — and cannot grow the set afterwards (row T-61: preserves). So T-20 (b) can select only u, the real
uid; p22 holds, and the stamp equals the passive one — the second of kub §5's four routes, measured with the
first on WSL2 (EV-29 arms 0 and 1 each delivered uid 1001).

What the re-read adds, and what it does not:
- It turns C1 from "required, not checked" (EV-30) into a runtime check in the product path. The T-08 SEALED
  comparison of the stamp with the allocated u catches a wrong real uid only; an unequal effective or saved
  uid — this route's precondition — reached SEALED unseen before the re-read (engine-requirements §8, C1 row).
  The premise narrows from "the call is coded with equal values" to "the bootstrap runs the shared drop with
  its re-read", which the regression's injection cases watch.
- It is one reading at one instant, before the capability clear, the filter and `execve`. Later changes are
  not re-read; they are bounded by the kernel's own-set rule and the absence of `CAP_SETUID` (T-61).
- It reads uids, not capabilities. A task that kept `CAP_SETUID` would pass it and could change uid later;
  that is the first half of C2, carried by the bounding-set clear, the clear that follows the re-read and
  `no_new_privs` (EV-05, EV-74), not by the re-read.
- It reads in the child's user namespace, which is the initial one: step 0's `clone` creates no user
  namespace (optb step 0) and C3 gives the identity map, so the values are kernel uids. A namespace the
  agent makes later (S1 absent) renames its uid without changing the kernel uid (T-62; EV-60).
- It does not re-read the gids; this route concerns the uid comparison only.

The departure that remains is T-67 branch (a) with the re-read absent or defective, which the G5
preservation file records as not preserving IG-02. The route is stopped at the uid-selection step, before
any endpoint question, so A-07 enters only the reachability of the accepted event, not the stop.
Preservation rows relied on: T-61 (preserves under the premises) and T-67 (branch a names the departure).

## 5 Disposition
**supported under stated premises** (the same value as the `disposition:` field) — a design-layer and
kernel-semantics conclusion, not a claim about the deployed system.
- Premises that must hold: C1 with its check — the bootstrap runs the shared drop with `setresuid(u, u, u)`
  and the `getresuid` re-read before the filter; the first half of C2 / S4 (bounding set cleared,
  `no_new_privs`, capability sets cleared) so that the own set cannot grow later; `nosuid` on the runtime
  and /work; the kernel at the pinned tag (AA-02); the common abstraction of the frozen revision.
- Evidence limit (configuration, substrate, run dates): the re-read run (2026-10-18) and EV-74 (2026-09-11)
  are the sandbox code on direct WSL, kernel 6.6.87.2-microsoft-standard-WSL2, under the diagnostic policy,
  not the engine or a real agent; the re-read's negative path was exercised by test-build fault injection,
  its unequal-value branch only read in the code; EV-70 is the 2026-08-18 probe in Docker on the WSL2 VM;
  EV-29's own-uid arms are one run on WSL2 (2026-10-14), the native-Linux VM arm pending.

## 6 What remains
- Residual: a configuration-failure route that must not land in the exclusion (02 §0.3). With C1 absent
  and the re-read removed by a later refactor, the route still needs an endpoint of the row whose uid was
  selected (A-07) or a G1 installation error, so a C1 failure alone yields a discarded frame, not a wrong
  label; this bounds the consequence and is not relied on. Coverage uncertainty: none beyond the premises.
- Design obligations surfaced for the engine: keep the re-read in the shared drop and its two injection
  cases in the regression (BUILD-PLAN's re-read check), so that a refactor of step 11 is caught (T-07). The
  earlier obligation of this file — a post-drop self-read before SEALED — is met in the sandbox code.
- Cross-references: the PLAN's pre-registered hypothesis names "C2 and spawn step 11"; this route's stop is
  C1 inside step 11, not C2's `unshare` deny — 02 §4.1 item 2 already separates them, so no disagreement.
  R-G5-04 (foreign map, q10), R-G5-07 (real-uid change, C-06), R-G2-05 (the D_22 remainder), R-G1-02 (a
  comparand not equal to the lease's rendering). kub §6 C1 touched (its "no runtime check" is superseded by
  the design text); C2 touched as the posture that keeps the set at `{u}`; obligations #2 (channel-to-agent
  binding) and #6 touched as the posture they presume. The G5 preservation rows T-61 and T-67 (a) still say
  C1 is unchecked; change request CR-G5-03 asks for their re-read.
