# R-G2-13 — A labelled acceptance lacks the required current comparison through an unrefined decision path outside the named cache/fallback cases.

## 1 What the adversary does
A labelled acceptance lacks the required current comparison through an unrefined decision path outside the named cache/fallback cases.

## 2 How it would produce false attribution
- **Nature of the slot.** This is the C-04 refinement slot of 02 U-02: the explicit remainders of the
  comparison cells. It holds every history in which some contributing fragment did not undergo the equality
  decision (p41) by neither a cached first-fragment credential (q14, R-G2-07) nor an identified
  header/body/OOB fragment reaching acceptance unchecked (q15, R-G2-02); or in which the decision did not
  require v(f) = e_r with the original comparand (p42) by neither a row chosen or rewritten from the
  observed value (q16, R-G2-08) nor a snapshot, payload or pid identity or a wrong equality result
  (q17, R-G2-09).
  B(R-G2-13) = (D_41 ∧ ¬(q14 ∨ q15)) ∨ (D_42 ∧ ¬(q16 ∨ q17)).
- **What would have to be true for it to be a route:** a decision path in the product receiver that admits
  a fragment without the equality — a fast path for a channel "known" after hello, a path for a frame with
  a zero-length or sentinel-shaped body, a DRAINING or bye path that skips the check, an error-recovery or
  resynchronisation path, a comparand drawn from a configuration default instead of the row — or a
  comparison whose result is ignored on some branch. The adversary's part is to drive the receiver onto
  that path with its own protocol input and timing (A-02, A-06), from a holder with uid ≠ u_r (a same-uid
  sender is X itself, or an IG-02 failure owned elsewhere). Configuration: all three branches under the
  common abstraction (agent ↔ engine leg).
- **Transitions traversed:** T-23 (the decision), T-24, T-25 (phase gating, where a path that skips the
  check would branch).
- **Sufficient condition violated:** C-04 (p41 or p42). Why it would be a wrong attribution: a fragment
  admitted without the current comparison carries its sender's stamp unexamined, so its sender need not
  be the row's execution.

## 3 What stops it
One comparison point lies on the only path from recvmsg to the buffer and every phase passes through it, which is the closing property of R-G2-13 in PLAN §Follow-up plan after U, established by a structural reading of the C reader and of receive_step, with root unit tests across STARTING, ACTIVE and DRAINING and a pre-read test for a CLOSED session, within the limits section 5 states.

The slot is the remainder of the comparison cells: a decision path that admits a fragment without the
equality, or a comparison whose comparand or result is not the one C-04 requires. The structural reading
below was done for this file on the C reader of engine commit 7b4ab727, which removed the jansson parse of
the body that the reader of 3ec67985 ran after the comparison (registry §2, version 9); it agrees with val
§R-G2-13, with EV-172, and with EV-171 in every clause but the parse, which EV-265 supersedes.

**One comparison point, one path.** The data channel's only recvmsg is transport.c:154 in
w2_recv_credential; before that function returns a positive count, w2_ancillary requires exactly one
credential, no rights, pid > 0, a uid that is not 0, the overflow uid or the invalid value, and equality with
the bound expected uid (transport.c:116–117, :160). w2_frame_receive is its only caller (transport.c:224) and
counts the bytes only after a positive return (:230); the length is decoded only from the four counted
header bytes, and a body is copied out only when whole, with no parse in C (:232–238; EV-265). Every
failure, EOF included (:226), unexpected ancillary, an out-of-band byte (:219–221) and the deadline (:222,
:229, :237), takes the one exit that kills the reader (:239), after which every call returns −1 at :214
(EV-171, line numbers from L239 on one less at 7b4ab727; EV-265). On the Python side
receive_step has one caller, phases.py:64; it calls the C reader first, returns on a partial or rejected
read, and only after a whole frame runs the strict parse, the schema and the phase rule, then builds the
package's one VerifiedContext; its caller records receive_rejected with no subject and ends the row
(EV-172). The message objects that carry a context are built only by receive.py's _message, which only
receive_step calls.

**Every phase through it.**
- STARTING, ACTIVE and DRAINING: the receive callback runs receive_step for a current Channel in any of the
  three states (phases.py:56–64), and the phase rule is a parameter that receive_step calls only after the
  comparison has passed for every fragment (receive.py:284–294). A root unit test drove a whole frame from
  another pool uid and a frame whose header came from the expected uid and whose body came from another,
  under each of the three phase rules and three frames: all ended receive_rejected with the phase rule never
  called, and the control test reached each phase result from the expected uid (EV-173). A first fragment
  from another uid, a uid change between fragments of one frame and a frame from another pool uid were each
  rejected before a frame formed (EV-174).
- CLOSED: receive_step checks Session.admission before reading and returns before any call into the C
  reader (receive.py:282–283); the test observed no call (EV-239). The callback also returns for a Channel
  that is not current (phases.py:62–63).

**Comparand and result.** For D_42 ∧ ¬(q16 ∨ q17): the comparand is the Session's expected uid, passed in at
each call (receive.py:284) and bound in C on first use, a change killing the reader (EV-236); the observed
uid neither selects nor writes a row and never reaches Python (EV-169, EV-174); the result of w2_ancillary is
acted on at the one call site, where −1 propagates to the reader's exit (transport.c:160, :226). For
D_41 ∧ ¬(q14 ∨ q15): every fragment is one positive-length return of that recvmsg, and none is counted
before its own comparison, so no fragment reaches the frame without the equality. One other credential read
exists outside the engine: the spawner's pre-exec bootstrap read of SEALED (spawner.c:170–186) applies the
early-failure form of w2_ancillary and its own uid check, and yields no data message and no subject (conn
E-01: an independent fixed-length stage).

kub §5's two-valued property (EV-29) bounds the stamp and does not depend on the engine checking correctly;
it is a premise of what the comparison compares, not support for the comparison. No preservation row is
relied on; rows T-23 … T-25 argue I under the receive rules, and this file argues that the histories outside
them are empty within the premises and limits stated.
