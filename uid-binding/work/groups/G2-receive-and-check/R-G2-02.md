# R-G2-02 — A contributes unchecked header/body or OOB bytes to a frame accepted using the checked remainder's identity.

## 1 What the adversary does
A contributes unchecked header/body or OOB bytes to a frame accepted using the checked remainder's identity.

## 2 How it would produce false attribution
- **Preconditions:** the adversary — or, under the stipulated input A-07, a second holder of the agent end
  with another uid — writes bytes meant to be interleaved into one frame: the 4-byte length header from one
  sender and the body from another, a single byte in the middle of the body from the foreign holder, an
  MSG_OOB byte, or data that a second reader consumed and re-injected. The route needs the engine to accept
  the frame on the identity of the fragments it did check and to let the unchecked bytes ride along.
  Configuration: all three branches under the common abstraction (agent ↔ engine leg).
- **Transitions traversed:** T-20 (the writes, from one task or several; T-60 siblings; T-64's OOB path,
  which stamps alike) → T-21 → T-22 → T-23 (per fragment) → T-24 → T-25.
- **Sufficient condition violated:** C-01 p12 (every byte has a current recvmsg witness) or C-04 p41 (every
  contributing header/body fragment underwent the equality decision).
  B(R-G2-02) = (D_12 ∧ ¬q03 ∧ q04) ∨ (D_41 ∧ ¬q14 ∧ q15). Why it is a wrong attribution: a byte whose own
  stamp differs from expected_uid (the foreign holder's) would be labelled with the row's execution, so for
  that byte Exec(b) ≠ L(a).execution. Bytes from same-uid siblings of the same P_X are not this route: they
  are one principal (W2.1, justification row 1 of the preservation file).

## 3 What stops it
T-23's comparison of every positive-length return, the four header bytes included, and T-21's close on any
OOB/POLLPRI byte cut the route at the fragment. Design text (conn at the fourth-revision blob
0c16e567a34aa441): E-02 receive step 4 (L462–464) — every positive-length return is checked and only then
enters the buffer; a failing fragment discards the whole partial frame and closes; step 5 (L465) — the
length is decoded only after all four header bytes passed; the source note of the stream switch
(L1223–1226) — with SO_PASSCRED a receive return ends where the credential changes, so bytes of a different
stamp arrive as a separate return and are checked on their own, header included; step 2 (L456–458) —
POLLPRI/OOB triggers close and is never spliced into the normal stream; no second reader consumes the
channel.

Realization in the prototype (commit 3ec67985). w2_frame_receive asks recvmsg for at most the remaining
header or body length, adds a return to the counted bytes only after w2_ancillary accepted its credential,
decodes the length only from four counted header bytes, and on any failure kills the reader, after which
every call fails (EV-171, read at transport.c:211–240 of 3ec67985 on 2026-10-19; at 7b4ab727 the same
function is L211–239 with the C-side body parse gone and the comparison unchanged, EV-265). recvmsg places the bytes in the
reader's fixed array before the comparison; uncounted bytes are never read afterwards, so the design's
"only then enters the buffer" holds in the form "only then counts" (EV-171 note; val row 164, wording
approved by the user 2026-10-19). Root unit tests rejected a frame whose header came from the expected uid
and whose body from another uid in each phase rule, and a uid change between fragments of one frame, before
a frame was formed (EV-173, EV-174). A POLLPRI byte kills the reader (transport.c:219–221) and an
out-of-band byte ended the row with receive_rejected (EV-182). Preservation rows relied on: T-21, T-22,
T-23, T-24. The same-execution writers of T-60 are retained by the ledger and are not cut: they are the
row's own execution.

## 6 What remains
- Residual and open questions: the OOB-path memory-safety residual (EV-27) is a kernel-defect item and
  belongs to R-G5-01's declared exclusion, not to this route; whether the production allow-set permits an
  MSG_OOB send at all is part of the S2 `[S]` item, which this route does not need because the engine ends
  the row on any OOB byte; the C-04 remainder outside the cached-credential and identified-fragment cases
  is R-G2-13.
- Design obligations surfaced for the engine: keep the header read sized to the remaining header length so
  that the four header bytes pass the same comparison as body bytes; keep the POLLPRI outcome terminal for
  the reader.
- Cross-references: R-G2-07 (a cached first credential), R-G2-01 (no witness at all), R-G2-13 (remainder),
  R-G5-01 (kernel defect). Obligation #2; condition C4.
