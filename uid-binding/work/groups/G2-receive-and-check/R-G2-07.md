# R-G2-07 — A appends another sender's bytes after a first credential check and a cached frame credential admits them.

## 1 What the adversary does
A appends another sender's bytes after a first credential check and a cached frame credential admits them.

## 2 How it would produce false attribution
- **Preconditions:** a first fragment of a frame is sent by a task whose stamp equals the row's expectation
  (the adversary's own task in P_X). Later fragments of the same frame come from a sender with another
  stamp — a holder of the agent end under the stipulated input A-07 with uid ≠ u_r, or a task whose uid
  departed (T-61 / T-67, G5's inputs). The route needs the receiver to have fixed the frame's identity on
  the first fragment and to admit later fragments without comparing them. Same-execution writers that
  jointly produce a frame (T-60) are not this route: each fragment then carries u and the frame is X's.
  Configuration: all three branches under the common abstraction (agent ↔ engine leg).
- **Transitions traversed:** T-20 (first sender) → T-21 → T-22 → T-23 → T-20 (second sender) → T-21 → T-22
  → T-23 → T-24; T-60 for the retained same-execution case; T-63 for the possession input.
- **Sufficient condition violated:** C-04 p41 (every contributing header/body fragment underwent the equality
  decision). B(R-G2-07) = D_41 ∧ q14. Why it is a wrong attribution: the later fragments' bytes have a
  sender whose uid is not u_r, yet the frame is labelled with row r's execution.

## 3 What stops it
The per-fragment comparison: every positive-length return is compared to expected_uid, and no
first-fragment credential is cached for later fragments. That cuts the route at the second sender's first
fragment. Design text (conn at the fourth-revision blob 0c16e567a34aa441): E-02 step 4 (L462–464) — every
positive-length return is checked against the original immutable expected_uid and only then enters the
buffer; the source note of the stream switch (L1223–1226) — with PASSCRED a credential change ends the
receive return, every fragment including the length header is checked before it joins the FrameReader,
so every normal-stream byte of a dispatchable frame matches the original expected uid, not only the first
fragment or the hello. The FrameReader's common-uid field (L448–450) is a result of the per-fragment
equality, not a cache consulted for admission.

Realization in the prototype (commit 3ec67985). Each call of w2_frame_receive compares the credential of
its one recvmsg with the expected uid passed in for that call (transport.c:224 → w2_ancillary,
transport.c:116–117; EV-171). What the C reader binds on first use is the fd, the socket cookie and the
expected and overflow values passed by the caller, not an observed credential, and it dies if any of them
changes (EV-236, read at transport.c:216–218 on 2026-10-19); the value passed is the row's write-once
expected_uid (EV-186, EV-187), and the VerifiedContext's sender uid is that value, the observed uid never
leaving C (EV-169, EV-186). Root unit tests rejected a uid change between fragments of one frame, a first
fragment from another uid, and a header from the expected uid followed by a body from another, each before
a frame was formed (EV-173, EV-174). Preservation rows relied on: T-21, T-23, T-24; T-60 for the same-uid
writers.

**Composition:** the kernel's segmentation by credential (EV-88 [R]) makes a per-fragment check possible;
the design's per-fragment rule (EV-78 [S]) is realized by EV-171, EV-236, EV-186 and EV-169 [R] and
exercised by EV-173, EV-174, EV-187 and EV-291 [M]; EV-12 and EV-180 say why the snapshot form is absent.
The change of sender has been placed inside the four-byte header, at the header/body boundary and inside
the body (EV-251 [R] for EV-174's split positions) and on the frame's last byte, after every earlier
fragment had passed (EV-291 [M], whose negative control shows that a comparison on header fragments only
fails the case). EV-48 is the lab engine and a staged configuration. No necessary item remains `[S]`; the
result is not measured end to end.

## 5 Disposition
**supported under stated premises**
- Premises that must hold: C1 (a sender's stamp is one value; realized and observed, EV-212, EV-213); the
  kernel at the pinned tag (AA-02); the second sender's uid ≠ u_r (a same-uid sender outside P_X is an IG-02
  failure, R-G4-01 / R-G5-06 / R-G5-07); configuration: all three branches on the agent ↔ engine leg.
  Design-layer and kernel-semantics conclusion with the prototype's checked realization; nothing here is a
  claim about the deployed system.
- Evidence limit: integration run 20261019T011226Z-engine-pool-70000 (2026-10-19), its root unit suite with
  senders at test-catalog uids; the last-byte case of commit b262e80e (tests and the integration runner only,
  no engine or sandbox code changed) in run 20261020T154357Z-engine-extra-evidence-rerun (2026-10-20, same
  host and kernel, runner as root, senders at uids 60000 and 60001), with its negative control by a planted
  transport.c defect in a copy of the engine tree. Shared limits: [coverage-uncertainties § Shared evidence boundary](../../convergence/coverage-uncertainties.md#shared-evidence-boundary-every-route-not-repeated-below). The checks' own limits as val gives them: the
  negative frames share one code path and differ only in the failure position; a wrong-uid case through the
  full lifecycle exists only in STARTING; the split cases drive the C reader and receive_step directly in the
  root unit suite, not through an integration case.

## 6 What remains
- Residual and open questions: same-uid joint writers remain one principal by W2.1 — the route does not
  separate members of P_X and the design does not claim to; the C-04 remainder outside the cached and
  identified-fragment cases is R-G2-13.
- Design obligations surfaced for the engine: keep the comparand of every call the row's expected_uid, so
  that the reader's first-use binding stays a binding of the caller's values and never of an observed
  credential.
- Cross-references: R-G2-02 (an identified unchecked fragment), R-G2-09 (a held foreign endpoint with a
  snapshot or wrong equality), R-G2-13 (remainder), R-G4-01 (surviving same-uid task). Obligations #2 and
  #3; condition C4.
