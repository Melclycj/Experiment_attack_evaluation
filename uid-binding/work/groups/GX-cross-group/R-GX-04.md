# R-GX-04 — A survives an old engine/spawner epoch while a replacement engine treats the same uid pool as empty and attributes its messages to new allocations.

## 1 What the adversary does
A survives an old engine/spawner epoch while a replacement engine treats the same uid pool as empty and attributes its messages to new allocations.

## 2 How it would produce false attribution
- **Preconditions:** engine epoch 1 launched execution A at pool uid u (T-01 … T-11). Control is lost
  (T-49): engine 1 crashes (K-08) or its control link fails; spawner 1 dies before its sweep finishes
  (SIGKILL or OOM, conn L868) — otherwise it kills and reaps every record and A dies (conn L860–861; G4
  preservation, row T-49) — or spawner 1 lacks CAP_KILL in A's user namespace (conn L842–854). A's PID 1 is
  reparented and keeps running at u with its fd 3. The supervisor confirms the isolation domain empty
  without having found A — the FALSE branch of 03's parameter MM10_SupervisorFactSound, which 03 did not
  run. Engine 2 starts with a free pool (T-49 tail); T-01 reserves u for B; T-03 at spawner 2 has no record
  of A; B launches. For A's bytes to reach B's row, A must hold a descriptor to B's socketpair (A-07): A's
  own fd 3 names engine 1's socketpair, whose engine end died with engine 1's process or sits unread in a
  surviving engine 1 whose rows are all CLOSED; no transition of the frozen text gives A a copy of B's end
  (01 A-07; spawner 2 creates B's pair after A exists and B's bootstrap runs close_range — G1 rows T-04,
  T-06). As in R-G4-01 and 03 run 2c, both legs are needed: the survivor and the endpoint. Configuration:
  all three under the common abstraction of the frozen revision.
- **Transitions traversed:** T-01 … T-11 for A in epoch 1; T-49 (control loss; spawner death or sweep;
  the supervisor; the new epoch); T-44 (A's lease quarantined in epoch 1, never recovered); T-01, T-03,
  T-04 … T-09 for B in epoch 2 (G1 facts); T-20 (a) by A into B's channel (A-07); T-21 … T-24 at B's row
  ending in a D-ACC labelled B.
- **Sufficient condition violated:** C-06 p61 — A's allocation interval, never released, is open-ended (02
  §1) and overlaps J_B while assigning u — cell D_61 with ¬q23 (two engine processes, two epochs) and q33
  (an earlier epoch of the same cell that B's epoch succeeded after control loss); B(R-GX-04) = ¬H ∧ D_61
  ∧ ¬q23 ∧ q33 (02 §4; CR-A-11). p62 fails as well (a task at u inside J_B outside P_XB), and C-07 as the
  ledger lists. Why it is a wrong attribution: the stamp is u, B's expected_uid is u, the comparison
  passes, the label names B, and Exec(b) = A. The cell is settled by 03 v4 §1.1 (iii) (CR-F-07, from this
  folder's CR-GX-01): the T-49 epoch end holds in the model, while for 02 §4's cell assignment an
  unreleased lease of a lost epoch keeps its interval open, so this history is R-GX-04's (D_61 ∧ q33) and
  not R-G4-01's; the model's NewEpoch retirement is the modelling device whose soundness is the MM-10
  premise.

## 3 What stops it
Before a replacement engine in the same cell restarts its pool, the old cell's own cgroup is killed and must report populated 0 in cgroup.events — a kernel-held fact on which the trusted supervisor releases, keeping no safety-relevant state — under the deployment precondition that every member of the cell sits in that cgroup and no agent can leave it. The design states this since the fifth revision (conn E-04 L930–937; rr E-08 L763–764, L888–890; engine-requirements row 218, tagged deployment; 01 v11 MM-10 stated, AA-04 narrowed): the cell's engine, spawner, file worker and all executions sit in one exclusive cgroup; the supervisor writes cgroup.kill and waits until cgroup.events reports populated 0; the confirmation never rests on an engine's or spawner's self-report or on a /proc uid scan (conn L931–932; rr L763); a pid-namespace reap is not used as this fact, because its result reaches the init's parent once and a restarted releaser cannot re-read it (conn L933–934); the supervisor releases only on the fact and keeps no safety-relevant state, so its crash only keeps the new epoch from starting and after a restart it re-reads the kernel's fact (conn L934); an agent cannot leave the cgroup — the sandbox mounts no /sys and the agent has no write access to move a cgroup (conn L935); the cgroup is managed by host init and supplied by the deployment (conn L935–936; rr L889–890). The old epoch's executions and leases are never recovered, and a spawner lost to SIGKILL or OOM is residue for the supervisor, never faked as empty (conn L937–940).

Why this cuts the survivor leg: A's PID 1 and every task it forked — orphans reparented outside the tree and setsid sessions included — inherit the cell's cgroup and cannot move out of it, so the kill reaches A whether or not spawner 1 survived to sweep and whether or not it held CAP_KILL; populated 0 is reported only when no member is left, so a new engine whose pool is released on that fact starts with no task of the old epoch alive at any pool uid of the cell. The history of section 2 needs the supervisor to confirm the domain empty without having found A — the FALSE branch of MM10_SupervisorFactSound — and under the stated method that branch requires a departure from the premises of section 5 (a cell member outside the cgroup, an agent able to move itself, or a releaser acting on something other than the kernel's fact), which is a T-67 configuration failure, not an adversary action. G4 preservation row T-49 preserves "under MM-10"; 03 §3 records the new epoch's initial state as an I-state under the premise that the fact is sound, which is now the premise of a stated method.

Three stated mechanisms still narrow the history before the supervisor's step, now realized in the prototype: (1) a spawner that outlives engine 1 stops and reaps every SpawnRecord and exits (conn E-04; G4 row T-49), and the kernel zaps each P_X when its PID 1 dies (EV-17; G4 rows T-41, T-42); (2) engine 1 quarantines its unconfirmed leases, reserves nothing after control loss and exits (G4 rows T-44, T-49); (3) the new epoch's own checks cannot see A — T-01 reads its own pool, slots and WorkspaceRecord and T-03 sees only spawner 2's records (G1 preservation, rows T-01 and T-03) — which is why the cut sits with the cgroup fact and not with the engine. The endpoint leg is G1's construction: spawner 2 creates B's socketpair after A exists and hands its engine end only to engine 2 (G1 rows T-04, T-09); B's bootstrap closes everything above fd 3 before execve (G1 row T-06; EV-64); A acquires B's end by no transition of the frozen text (01 A-07, stipulated). This leg is not relied on as the cut. Preservation rows relied on: G4 T-41, T-42, T-44, T-49 and §D4's R-GX-04 line; G1 T-01, T-03, T-04, T-05, T-06, T-09.

## 5 Disposition
**supported under stated premises** — the same value as the `disposition:` field. The method the route's cut needed is now stated (MM-10), its kernel half is measured on the development host, its sandbox half is realized in the prototype, and the route's two-epoch history was run once on the development host with a stand-in gate (EV-295–EV-299); what remains belongs to the deployment, which step4-brief §1 counts as premises.
- Premises that must hold: the cell's engine, spawner, file worker and every execution are placed in one exclusive cgroup managed by host init, and the releasing party starts a new engine of the cell only after writing cgroup.kill and reading populated 0 in cgroup.events, never on a self-report, keeping no safety-relevant state (engine-requirements row 218, a deployment precondition; AA-04 as narrowed in 01 v11); no agent can leave that cgroup — no /sys or cgroup file system in the sandbox (realized, EV-282) and no write access to any cgroup.procs outside the cell (a deployment precondition; observed for one configuration, EV-279), which also rests on the agent's S1 / C1 posture (no capability, no user namespace: EV-213, EV-214; AA-11); the pool is exclusive to one engine at a time in the cell (U-05; row 252 — a concurrently running second engine is R-G5-06, not this route); every member's uid stays u after T-07 (C1 and the first half of C2 — no CAP_SETUID in the initial user namespace; departures are G5's); the endpoint leg is stipulated (A-07); the kernel at the pinned tag (AA-02). A departure from any of these is a T-67 configuration failure. This rests on the frozen design as revised, kernel behaviour measured on the development host and the prototype's checked realization; it is not a claim about a deployed system.
- Evidence limit (configuration, substrate, run dates): the cgroup behaviour is one probe run on the WSL2 development host (kernel 6.6.87.2-microsoft-standard-WSL2, cgroup v2 unified hierarchy, systemd 255, 2026-10-19), with sleep processes standing in for the engine, spawner and executions and a script standing in for the release gate (EV-278–EV-280); E2 tested the cgroup v2 write-permission path only, with no case of a task holding CAP_SYS_ADMIN or able to mount a cgroup file system (the sandbox gives neither); no supervisor has been built. The two-epoch run (EV-295–EV-299) is one run on 2026-10-20 on the same substrate (WSL2 6.6.87.2-microsoft-standard-WSL2, cgroup v2), engine commit b262e80e (tests and the integration runner only; engine and sandbox code as at 9981dd7b): its release gate is a function of the integration runner standing in for the deployment's supervisor, the runner created the cell's cgroup itself rather than host init, and A was a linger fixture silent after its hello that made no attempt to leave the cgroup or to reach engine 2's rows. The sandbox mounts were read at 7b4ab727, unchanged from 3ec67985; the control-loss cases cover a spawner that survives and sweeps and, in the two-epoch run, a spawner SIGKILLed with A alive (EV-296), the kill faults are injected in the test build (EV-204), and the no-pin absence is a text search (EV-235). The lab engine's d6 of 2026-08-15/16 measured the consequence with no gate; the bounded TLC check did not run the MM-10 FALSE branch (03 §5.2, §5.5). All three configurations. ## 6 What remains

The IG-10 split of 03 v4 is not used. Coverage uncertainty left: the no-leave premise was observed for an unprivileged member under one cgroup ownership layout; a privileged agent is outside the premises by the S1 / C1 posture, not by a cgroup check.
