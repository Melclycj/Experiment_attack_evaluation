# R-G1-06 — This engine's spawner launches A's clone with another row's allocation uid against A's own record, and A's bytes reach that row's endpoint and are accepted under its label.

## 1 What the adversary does
This engine's spawner launches A's clone with another row's allocation uid against A's own record, and A's bytes reach that row's endpoint and are accepted under its label.

## 2 How it would produce false attribution
- **Preconditions:** a trusted-actor correspondence error, not an adversary privilege: the spawner applies setresuid at T-07 with u_B, row B's lease uid, to the clone of record A, whose own SpawnRecord assigns u_A; A reaches execve at u_B; A holds B's endpoint (A-07, stipulated — on A's own endpoint the stamp u_B fails A's row's expected u_A, as 02 §1 states) while row B is STARTING or ACTIVE with its channel installed; A sends. Configuration: all three under the common abstraction (01 AA-06).
- **Transitions traversed:** T-02 (A's request carries u_A), T-03 (A's record with u_A), T-04, T-05, T-07 (the wrong value applied), T-08 (SEALED), T-09, T-10, T-11, T-20 … T-24 at row B.
- **Sufficient condition violated:** C-05 p53 (during J_r no clone of this engine's spawner other than X_r is launched with A_r.uid as its T-07 uid while its own SpawnRecord assigns a different uid); cell D_53 → R-G1-06 unconditionally; B(R-G1-06) = ¬H ∧ D_53. C-06 p62 is affected as a consequence: A's tasks at u_B are not members of P_XB. The acceptance at row B carries stamp u_B = row B's expected uid with origin X_A: ¬P_acc. The ledger's boundaries: a second allocation whose own record assigns u_B is R-G1-05; another engine's clone is R-G5-06 / R-GX-04; a same-spawner clone at u_B before B's reservation is a pre-existing holder (D_62 q25 → R-G5-06).

## 3 What stops it
The spawner's per-fragment SEALED check at T-08 — the kernel-stamped uid of the bootstrap's bytes must equal the record's uid and the pid the record's child_pid — fails the record before COMMIT, so a clone launched at another row's uid never reaches execve. At T-07 the bootstrap drops to SpawnRecord.uid (optb step 11; preservation row T-07); at T-08 it writes SEALED into the channel, the kernel stamps those bytes with the sender's real uid (EV-07; PASSCRED set at T-04, EV-179), and the spawner reads them on the engine end with a control buffer, requiring per fragment that the stamped uid equal the record's allocated value and the pid equal child_pid (conn L292–293; row T-08). In the prototype the spawner's bootstrap reader calls recvmsg with a control buffer per fragment, requires through w2_ancillary the credential pid to equal the record's child pid, and clears the record's all-expected flag when a fragment's credential uid differs from the record's admission uid, is 0 or is the overflow uid; a SEALED with that flag cleared, an EOF or a malformed record fails the record before COMMIT (EV-210, spawner.c:170–188, confirmed at commit 3ec67985 on 2026-10-19); a FAIL emitted before the drop yields only spawn_failed with its stage (EV-109; EV-210, EV-211). A clone that landed at u_B against a record assigning u_A stamps u_B ≠ u_A, and the record fails: spawn_failed, no prepared, no COMMIT, the child killed and reaped (conn L129, L302; T-13, T-41, T-42 as facts); the adversary never begins (AA-09, IG-11). The drop's shape is realized too: one shared drop sets setresuid with three equal values, re-reads them with getresuid and fails unless all three equal the uid, and the seccomp filter is installed only after it returns (EV-212); every agent observed in the integration run had real, effective, saved and filesystem uid equal to its pool uid (EV-213). Two further cuts bound the neighbouring errors. The record case: a spawn request whose uid or gid differs from the workspace's registered value is refused at T-03 before clone (si L271–272; EV-209; EV-208 the bad-uid and bad-gid regression cases; row T-03), and a uid already in a live record is refused there too (conn L112; EV-209, EV-207). The row case: even past T-08, A's own endpoint carries expected u_A, so A's stamp u_B is rejected at A's row (T-23 fact), and reaching B's row needs A-07, which no transition of the frozen text produces (01 A-07; rows T-05, T-06). Under AA-04 the route's precondition does not arise; in the prototype it is unreachable by construction as well, since the bootstrap drops to the uid of the record's own plan workspace, which admission has required to equal the record's uid (see proposed evidence); the SEALED check is what makes a departure detectable rather than silent (02 §0.3).

## 5 Disposition
**supported under stated premises**
- Premises that must hold: AA-04 and AA-09 (the spawner and bootstrap run the code read at EV-210 / EV-212; the route is a departure of that code, detected by its own check); C1 (three equal values, now realized with a re-read, EV-212), so that "the uid the clone landed at" is one value; PASSCRED set at T-04 so that SEALED is stamped (R-G1-01's cut); the kernel semantics of the pinned tag (AA-02). A design-layer and kernel-semantics conclusion, with the spawner-side items realized in the prototype and checked; not a claim about a deployed system.
- Evidence limit (configuration, substrate, run dates): integration run and sandbox regression of 2026-10-19 and the re-read regression of 2026-10-18; the seccomp filter is installed after the drop. Shared limits: [coverage-uncertainties § Shared evidence boundary](../../convergence/coverage-uncertainties.md#shared-evidence-boundary-every-route-not-repeated-below). Limits of the checks: the SEALED uid-mismatch branch is read, not exercised; the re-read fault point precedes the getresuid call, so the failure exit is exercised and the unequal-value comparison is read (EV-148, EV-149); the startup-fault cases are faults injected in the test build.
