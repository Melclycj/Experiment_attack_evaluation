# R-G2-09 — A writes through a held foreign endpoint and a snapshot, payload/pid identity or incorrect equality decision admits it as the endpoint's execution.

## 1 What the adversary does
A writes through a held foreign endpoint and a snapshot, payload/pid identity or incorrect equality decision admits it as the endpoint's execution.

## 2 How it would produce false attribution
- **Preconditions:** possession is stipulated as the attacker input A-07: a task of execution Y, uid u_Y,
  holds a descriptor to execution X's agent end. No transition of the frozen text produces this state —
  T-04 creates the socketpair before the child exists, T-05 closes the spawner's copy of the child end,
  T-06 step 10 runs close_range above fd 3, the spawner is pre-forked before any channel exists (conn L347;
  optb step 10 and the spawner paragraph); the d2 naive-spawn leak is the measured origin of the
  hypothesis and the hygienic arm handed nothing over (EV-63, EV-64); the theft attempts of arm3 m2 / m3
  were refused (EV-49, EV-54, EV-55). The route needs u_Y ≠ u_X: a holder with uid u_X outside P_X is an
  IG-02 failure and belongs to R-G4-01 / R-G5-06 / R-G5-07, and a holder with uid u_X inside P_X is X
  itself (W2.1). It then needs the engine's decision to use something other than the current comparison
  of v(f) with e_r: a connect-time snapshot, a payload identity field, the delivered pid, or an equality
  computed wrongly (selector q17). Configuration: all three branches under the common abstraction
  (agent ↔ engine leg).
- **Transitions traversed:** T-63 (the possession, as input) → T-20 (Y's send stamps u_Y) → T-21 → T-22 →
  T-23 → T-24.
- **Sufficient condition violated:** C-04 p42 (every decision required v(f) = e_r with the original
  comparand and no observe-and-rebind or fallback identity source). B(R-G2-09) = D_42 ∧ ¬q16 ∧ q17. Why
  it is a wrong attribution: Y's bytes, stamped u_Y, would be labelled with X's execution.

## 3 What stops it
T-23's per-fragment comparison of the kernel stamp against the endpoint row's expected_uid — no
connect-time snapshot, no payload or pid identity — cuts the route at the first fragment: Y's stamp is
u_Y, the row expects u_X, the fragment fails, the whole partial frame is discarded and the session closes
(conn E-02 step 4, L462–464 at the fourth-revision blob 0c16e567a34aa441). The design uses no SO_PEERCRED:
kub §2.4 names it as the capture form deliberately not used, and conn E-01 (L136–138) forbids deriving
identity from it on the control channel; no payload identity (conn hello L522, VerifiedContext L572); the
pid is a diagnostic only (conn L573). kub §7.2 walks exactly this case: the channel selects which
expectation applies and the kernel supplies the value checked, so a holder sending as itself is rejected.
The holder's other option — attaching u_X instead of sending as itself — fails at the sending syscall (kub
§7.2, second case; EV-29 [M] on the WSL2 arm: an attached foreign uid failed EPERM and nothing was
delivered), and that alternative is R-G5-04's route with the R-G2-05 remainder, not this one.
Preservation rows relied on: T-20 (the stamp is the sender's real uid), T-23, T-24; T-63 (possession does
not enter I).

Realization in the prototype (commit 3ec67985). Every positive return on the data channel is compared in
C with the row's expected uid before it is counted, and a mismatch kills the reader (EV-171, read at
transport.c:116–117, :224–240 of 3ec67985 on 2026-10-19; the comparison is unchanged at 7b4ab727, EV-265); the comparand is the row's write-once expected_uid and the
observed uid never leaves C (EV-186, EV-169). A frame from another pool uid written to an execution's
channel was rejected before a frame was formed (EV-174), the unit form of a different-uid holder. The engine
reads no SO_PEERCRED and sets no socket option (EV-180); the install requires SO_PASSCRED = 1 on the
handed-over fd and faults otherwise (EV-177). The pid is only required to be positive on the data channel
(EV-171) and no code path looks up a pid (EV-235). Identity-like payload fields make every message type
invalid (EV-184).

Step 3 facts cited as bounded model results, not as design conclusions (03 §5.4, §5.5): run 1 — with
descriptor possession stipulated (A07 = TRUE) and the frozen double gate, no violation of I or of the goal
on any reachable state of the bounded subset; run 2b — with the membership half removed and A07 = TRUE, a
false acceptance is reached, but by a surviving member of the prior allocation with the same uid (R-G4-01's
history, D_62 q24), not by a different-uid holder; run 2c — with the gate removed and no A07, no goal
violation. In the subset, possession matters only where IG-02 already fails, which matches 02 §4.1 item 1:
descriptor possession alone is not a failure predicate.

**Composition:** the kernel stamps the sender's own uid regardless of who held the endpoint before
(EV-07 [R]) conjoined with the per-message comparison (EV-41 and EV-78 [S] realized by EV-171, EV-186 and
EV-169 [R], exercised by EV-174 and EV-293 [M]); EV-12 [R] says why a snapshot would not do and EV-180 [R]
that none is read. EV-293 is the route's own shape: a task at another uid holding a copy of X's agent end
itself, naming a live task of X as its pid, is rejected at receive_step with no context built, and the
rejection record carries no subject (EV-285 [R], EV-286 [M]); with EV-294 [M] as control, a /proc pid
lookup planted in transport.c fails both cases, so the pid is not consulted; EV-99 [S], the handoff precondition under which the comparison sees a stamp at all, is realized
by EV-177 [M] and EV-180 [R]; EV-29 [M] (WSL2 arm) bounds the neighbouring "send as A" alternative. The
acquisition items (EV-49, EV-54, EV-55, EV-63, EV-64, EV-86, EV-87) bear on whether A-07 is reachable,
which the route stipulates and does not argue. No necessary item remains `[S]`; the result is not measured
end to end, and the lab-engine rows EV-48 / EV-50 / EV-15 are a different code base.

**Proposed evidence (not yet in the registry):** a root unit case in which a different-uid task holds a
duplicate of an execution's agent end itself (not a separate writer at another uid) and sends a valid frame
with its delivered pid equal to a task of X, recording rejection and that the pid is not consulted. — registered as EV-293 and EV-294 (val row 168) (2026-10-21).

## 5 Disposition
**supported under stated premises**
- Premises that must hold: u_Y ≠ u_X (C-06 holds — IG-02 in the pre-state); C1 – C4, of which C1, C2 and C4
  are realized in the prototype (EV-212–EV-215, EV-179, EV-237) and C3's initial-namespace half is a
  deployment premise (S13); the kernel at the pinned tag; possession stipulated as A-07; configuration: all
  three branches on the agent ↔ engine leg. Design-layer and kernel-semantics conclusion with the
  prototype's checked realization; the Step 3 results are bounded model facts; nothing here is a claim
  about the deployed system.
- Evidence limit: integration run 20261019T011226Z-engine-pool-70000 (2026-10-19) with its unit and root
  unit suites. This route's cut does not rest on the production allow-set S2, and the clauses that keep
  CLONE_NEWUSER from the agent hold for any allow list the compiler accepts (EV-215). EV-29 ran on the WSL2
  arm only, 2026-10-14, with no seccomp; TLC bounds as 03 §5.2 states them; the holder cases of commit
  b262e80e (tests and the integration runner only, no engine or sandbox code changed) in run
  20261020T154357Z-engine-extra-evidence-rerun (2026-10-20, same host and kernel, runner as root, X at uid
  60000 and the holder at 60001), with negative controls by a planted transport.c defect in a copy of the
  engine tree. Shared limits: [coverage-uncertainties § Shared evidence boundary](../../convergence/coverage-uncertainties.md#shared-evidence-boundary-every-route-not-repeated-below). The checks' own limits: the holder's copy of the agent end is handed over by the test
  over SCM_RIGHTS, not obtained through a spawn defect; the sender holds CAP_SYS_ADMIN only so that it can
  name another task's pid, and not CAP_SETUID; the cases drive the C reader and receive_step directly in the
  root unit suite, not through an integration case; the absence of SO_PEERCRED is by text search.

## 6 What remains
- Residual and open questions: outbound confidentiality under A-07 is not protected by this mechanism — a
  holder reads what the engine writes to the endpoint (kub §7.4; X-10) — a different property, not false
  attribution; the acquisition footing of A-07 (the naive-spawn leak against the hygienic spawn; the
  pidfd_getfd exit window whose fix is absent at the pin, where the uid/gid first-layer match still
  confines theft to same-uid tasks) is Stream E and G5 material; a same-uid holder outside P_X is
  R-G4-01 / R-G5-06 / R-G5-07; the C-04 remainder is R-G2-13.
- Design obligations surfaced for the engine: keep the comparison the only identity decision on the data
  channel — no SO_PEERCRED read, no pid consultation; at T-09 (G1's), the handoff's unnamed-socket and
  SO_PASSCRED checks stay as the structural acquisition barriers the engine itself can verify.
